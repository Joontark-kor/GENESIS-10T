# 13. 예측 엔진 (연구 트랙, 기본 꺼짐)

폴라베어 규칙 "모델은 식, 계산기는 계산"을 넓힌다. **LLM은 말과 판단, 엔진은 예측.**
- 전처리: **사건 엔진** — 공개 월간 통계의 미래값을 분위수·표본으로 예측 → 폴라베어 식에 표본째 넣어 답의 구간까지 계산.
- 후처리: **물리 엔진** — 모델은 솔버를 짜지 않고 시나리오 스펙(템플릿 + 단위 붙은 파라미터)만 쓴다. 고정 솔버가 다시 계산해 일치/불일치/미지원을 표시. 답은 고치지 않는다(재시도는 1회, 그래도 다르면 경고).

계산기와 달리 예측 엔진은 틀릴 수 있다. 그래서 채점은 정답률이 아니라 확률 점수(MASE·CRPS·구간 적중률·Brier)로 한다.

## 격리

- 코드는 `genesis_predict/`(코어 밖). 코어는 이 패키지를 import하지 않는다(`tests/test_boundaries.py`).
- `genesis.harness.evaluate`에 옵션을 추가하지 않는다(폴라베어 옵션 금지 원칙). 실험은 `python -m genesis_predict.e1` 같은 별도 명령.
- 코어 반영은 아래 **수율 검사**를 통과한 뒤에만, 범용 훅 하나로.

## 수율 검사 (코어 반영 관문)

반도체 수율처럼 "켰을 때 실제로 득이 나는 비율"을 본다. 아래를 **모두** 만족해야 통과.

1. 봉인 시험지(S1·S2·S3)에서 미리 정한 기준 통과(아래 표). 개봉은 1회.
2. 시드 3회 반복에서 꺼짐·켜짐의 범위가 겹치지 않음.
3. 기존 회귀 세트(금융 544, 일상 420, 어려운 360, 다단계 240, 계산 없음 240)에서 켜짐이 꺼짐보다 범위 밖으로 떨어지지 않음.
4. 비용: 문항당 시간이 2배 이하.

## 엔진과 도구 (2026-11 확인)

| 부분 | 쓰는 것 | 이유 |
|---|---|---|
| 기준선 | seasonal naive, ETS, AutoARIMA (`statsforecast`) | 엔진이 넘어야 할 선 |
| 사건 엔진 | Chronos-2 small 28M (`autogluon/chronos-2-small`, CPU) | 공변량 지원, 가벼움 |
| 비교 | TimesFM 2.5 (Apache 2.0) | TimesFM 3.0은 비상업 라이선스라 제외 |
| 물리 | `pint`(단위), 닫힌 해 템플릿 10종, `scipy`로 교차 검증 | CPU, 4B 모델에 솔버 생성을 맡기지 않음 |

물리 템플릿: projectile, free_fall, pendulum, spring, incline, heat, cooling, rc_charge, ohm, ideal_gas. 범위 밖은 `unsupported`로 답하고 점수에 따로 센다.

## 평가 세트

| 세트 | 구성 | 채점 |
|---|---|---|
| 사건 개발 | 기준 시점 2025-06 이전, 300문항(점추정·구간·임계 확률·파생 지표·기권·비예측) | MASE, CRPS, 80% 적중률, Brier, 엔진 값 왜곡률 |
| 물리 개발 | 역학·열·회로 240 + 오류를 심은 답안 | 수치 정확도, 스펙 정확도, 오류 검출률, 맞는 답 차단율, 미지원 비율 |
| 외부 | PHYBench 중 템플릿 범위 | 범위 안 정확도 + 범위 비율 |
| 회귀 | 기존 다섯 세트 | 퇴보 없음 |

### 봉인 시험지

- **S1 과거 봉인**: 기준 시점 2025-12 이후 300문항(Chronos-2 공개 2025-10 이후).
- **S2 미래 봉인**: 아직 발표되지 않은 통계를 오늘 예측해 고정, 발표 후 채점. 학습 데이터에 있을 수 없음.
- **S3 물리 봉인**: 240문항, 낯선 파라미터(g=3.7 등). 정답은 해석해/독립 솔버로 만들고 검사 대상 엔진은 쓰지 않는다.
- 방식(`genesis_predict/sealed.py`): 설계 고정 후 별도 세션이 생성 → 비공개 저장소에 원본, 공개 저장소에는 SHA-256 매니페스트만. 한 번 열면 재사용 불가(코드가 거부).

### 통과 기준 (착수 전 고정)

- 사건: 폴라베어 + ETS 대비 CRPS 5% 이상 개선, 80% 구간 실제 적중 70~90%.
- 물리: 심은 오류 검출 80% 이상, 맞는 답 차단 2% 이하.

## 첫 실험 E1 — 엔진이 단순 기준선을 이기는가 (LLM 없음, CPU)

- 데이터: 한국 월간 시계열 60개(KOSIS/ECOS, 목록은 실행 전 고정), 기준 시점 6개(2024-01·04·07·10, 2025-01·04), 예측 1·3·6개월 → 1,080 예측.
- 엔진: seasonal naive, ETS, AutoARIMA, Chronos-2 28M.
- 통과: ETS 대비 시계열별 MASE 평균 5% 이상 개선, 시계열 부트스트랩 95% 구간이 0을 포함하지 않음, 80% 적중 70~90%.
- 해석: 이 기간은 Chronos-2 사전학습과 겹칠 수 있어 엔진에 유리하다. 여기서 못 이기면 Chronos-2 대신 ETS를 엔진으로 쓴다. 이겨도 S1·S2로 갈 자격일 뿐 효과의 증거는 아니다.

```bash
pip install statsforecast pint scipy            # CPU
pip install chronos-forecasting                 # Chronos-2 (가중치 다운로드 발생)
python -m genesis_predict.e1 --csv series.csv --engines seasonal_naive,ets,arima,chronos2 \
  --origins 2024-01,2024-04,2024-07,2024-10,2025-01,2025-04 --horizons 1,3,6 --out e1.json
```
